# Автоматизированное тестирование REST API сервиса управления токенами

Проект представляет собой набор компонентных и интеграционных автотестов для проверки REST API Spring Boot сервиса (`internal-0.0.1-SNAPSHOT.jar`), взаимодействующего со сторонним downstream-сервисом авторизации и выполнения действий.

Отчеты тестов сформированы с помощью **Allure Framework** с детальным описанием шагов (`Allure.step`), что обеспечивает прозрачность результатов для разработчиков, QA и нетехнических специалистов (бизнес-аналитиков и менеджмента).

---

## Стек технологий

* **Язык программирования:** Java 17
* **Тестовый фреймворк:** JUnit 5 (Jupiter)
* **HTTP-клиент:** REST Assured
* **Сервисная виртуализация:** WireMock (эмуляция downstream-сервиса на порту `8888`)
* **Отчетность:** Allure Framework + AspectJ Weaver
* **Сборщик проекта:** Apache Maven

---

## Инструкция по установке и запуску

### 1. Предварительные требования
* Установленный **JDK 17** или новее.
* Установленный **Apache Maven 3.8+**.
* JAR-файл тестируемого приложения (`internal-0.0.1-SNAPSHOT.jar`).

### 2. Запуск тестируемого сервиса
Сервис запускается с передачей секрета авторизации и URL внешнего мока:
```bash
java -jar -Dsecret=qazWSXedc -Dmock=http://localhost:8888/ internal-0.0.1-SNAPSHOT.jar
```

### 3. Запуск автотестов
#### Выполнение всех тестов:
```bash
mvn clean test
```
#### Запуск с исключением известных багов (с тегом @Tag("BUG")):
```bash
mvn test -DexcludedGroups=BUG
```
### 4. Генерация и просмотр Allure-отчета
```bash
mvn allure:serve
```

### Выявленные дефекты (Known Issues)
В ходе автоматизированного и статического анализа приложения были зафиксированы два архитектурных дефекта.
#### 1. Валидация токена отклоняет допустимые символы G–Z
   Описание: Согласно техническому заданию токен пользователя представляет собой 32-значную строку из латинских букв и цифр ([A-Z0-9]{32}). В реализации сервиса (UserRequest.class) установлена аннотация @Pattern(regexp = "^[0-9A-F]{32}$"), ограничивающая токен шестнадцатеричным диапазоном. Токены с буквами от G до Z ошибочно отклоняются с кодом 400 Bad Request.

Тест в коде: SecurityAndValidationTest.testTokenWithCharsBeyondHex() (отмечен @Tag("BUG") и @Disabled).

GitHub Issue: [#1](https://github.com/cl4ptp/Nord.Codes_TestTask/issues/1)

#### 2. Подмена статуса отказа авторизации кодом HTTP 500
   Описание: При отказе внешнего сервиса /auth (код 401 Unauthorized) класс ExceptionTranslator перехватывает исключение сетевого клиента и всегда отдает статус 500 Internal Server Error с сообщением Internal Server Error. Это маскирует стандартную пользовательскую ошибку аутентификации под сбой инфраструктуры.

Тест в коде: AuthTest.loginExternalAuthFailed() (отмечен @Tag("BUG") и @Disabled).

GitHub Issue: [#2](https://github.com/cl4ptp/Nord.Codes_TestTask/issues/2)
